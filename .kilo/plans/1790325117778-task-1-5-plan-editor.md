# Task 1.5 Plan Editor

## Keputusan

- `/ceo-dashboard/plans` berhenti memakai `CONTOH_PLANS`; halaman membaca tiga plan nyata dari tabel `plans` melalui Server Component.
- Tier (`STARTER`, `GROWTH`, `ENTERPRISE`) dan `id` immutable. Editor mengubah `name`, `priceMonthly`, `priceYearly`, serta seluruh properti `plans.features`, termasuk `addOnPricePerDevice`.
- `isActive`, penghapusan plan, dan penambahan tier baru berada di luar scope. Plan nonaktif tidak ditampilkan pada provisioning dan tidak dapat dipilih sebagai target action.
- Perubahan fitur entitlement berlaku saat konfigurasi dibaca ulang. Harga baru dipakai tenant baru dan renewal; subscription tenant existing tidak diubah retroaktif, sesuai PRD baris 354.
- Satu tombol simpan per plan memakai Server Action. Tidak ada optimistic update: pending, sukses, dan error ditampilkan eksplisit; setelah sukses `revalidatePath('/ceo-dashboard/plans')`.
- Setiap perubahan harga/fitur menulis `activity_logs` dengan action `plan.update`, resource `plan`, tier/id, daftar field yang berubah, dan nilai lama/baru yang aman. Tidak mencatat secret karena schema plan tidak mengandung secret.
- Validasi server adalah sumber kepercayaan: Zod membatasi UUID, nama, angka IDR non-negatif, harga tahunan nullable, integer limit non-negatif atau `-1` untuk unlimited, enum level, non-empty `cameraTypes`, dan boolean feature. Client validation hanya untuk feedback cepat.

## Data dan failure rules

- Update bersifat atomic pada satu row `plans`; kegagalan DB tidak boleh menampilkan sukses atau menjalankan revalidation sebagai hasil sukses.
- Audit failure mengikuti helper existing: mutasi valid tidak dibatalkan, tetapi error tidak boleh bocor ke client.
- Harga disimpan sebagai decimal string untuk menghindari floating-point drift. UI boleh memakai formatter IDR, tetapi action menerima nilai canonical tervalidasi.
- Active subscription rows tidak ditulis ulang. Pricing engine renewal membaca harga plan terbaru; existing invoice/subscription amount tetap historical.
- Plan dengan `priceYearly = null` dirender sebagai tidak tersedia, bukan `0`.
- Unknown feature key, missing feature key, invalid enum, angka negatif non-unlimited, atau `cameraTypes` kosong ditolak fail-closed.
- Error action tidak mengembalikan payload row penuh sebelum update, stack trace, cookie, atau session data.

## Validation

1. Jalankan `pnpm --filter @snapbox/web lint`, `pnpm --filter @snapbox/web typecheck`, dan `pnpm --filter @snapbox/web build`.
2. Jalankan self-check kontrak/action; verifikasi update mengubah tepat satu row dan `updatedAt` berubah.
3. Route test: anonymous redirect `/login`, non-CEO ditolak, CEO melihat nilai DB terbaru, unknown plan menghasilkan 404/result aman, catch-all tidak membayangi route eksplisit.
4. Browser test: edit tiap jenis field, unlimited toggle, invalid submit, reset, pending duplicate click, server error, success refresh, dan audit entry.
5. Browser test responsive: matrix overflow mobile, keyboard navigation, focus/error announcement, dialog/alert semantics, reduced motion, no console errors.
6. Regression test provisioning: plan editor tidak merusak `listPlanOptions`, plan lookup canonical, dan harga renewal yang mengambil nilai DB.
